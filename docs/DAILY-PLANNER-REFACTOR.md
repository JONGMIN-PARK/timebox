# 하루 계획 개선

기본 진입 화면을 하루 계획으로 변경했습니다. 중요 과제 3개를 정하고, 할 일을 15·30·45·60분 단위로 빈 시간에 배치한 다음 집중 타이머로 실행할 수 있습니다.

## 화면과 동작

- 계획 시간 범위, 배치된 시간, 집중 시간, 남은 시간과 완료율을 표시합니다. 겹친 일정은 별도 열로 표시하고 경고합니다.
- 시간표에 현재 시각과 완료 버튼을 표시합니다. 모바일은 시간표와 할 일 탭을 나누고 다크 모드를 지원합니다.
- 집중 타이머는 종료 시각을 저장하므로 백그라운드 전환 및 새로고침에도 유지됩니다. 완료 처리는 사용자가 선택합니다.
- 저장 실패 시 편집 내용과 할 일을 유지합니다. 날짜 및 프로젝트 변경 후 늦게 도착한 조회 응답을 차단하고, 실패한 항목만 되돌립니다.

## 내부 구조

화면을 시간 예산, 우선순위, 할 일 행, 집중 세션과 날짜별 계획 훅으로 분리했습니다. 공통 날짜 계산, 항목별 저장 큐, 알림 중복 억제를 독립 모듈로 추출했습니다.

백업 복원은 검증 후 트랜잭션으로 처리하고 부모 할 일 및 블록 연결 ID를 다시 연결합니다. 서버의 앱 생성, 작업 스케줄러, 시작 알림 및 버전별 DB 마이그레이션을 분리했습니다. Telegram 알림은 전송 임대와 전송 기록을 사용하며 사용자 확인 여부와 구분됩니다.

## 검증

- `pnpm test`: 날짜, 시간 예산, 동시 변경, 복원, 마이그레이션, 알림 및 타이머 단위 테스트 36개.
- `pnpm test:ui`: 데스크톱·모바일·태블릿·다크 모드에서 배치, 완료, 날짜 이동, 실패 시 입력 유지 및 타이머 재개 테스트 24개. API 응답을 모의 처리합니다.
- `pnpm build`, `pnpm lint`: 전체 패키지 검사. 기존 린트 경고는 남아 있습니다.

실제 PostgreSQL 데이터와 Telegram 계정으로 실행하는 통합 검증은 별도로 필요합니다. 서버 시작 시 기존 스키마를 보존하는 버전별 마이그레이션을 실행합니다. 알림 전송 후 기록 전에 프로세스가 중단되는 경우 재전송 가능성은 남습니다.

Windows UI 테스트는 설치된 Edge를 사용합니다. 다른 운영체제는 Playwright Chromium 설치가 필요합니다.
